# wpa11y design

Date: 2026-09-30. Status: approved in brainstorming, awaiting written-spec review.

## Goal

Replace the local pa11y-dashboard (and the Equalize Digital Accessibility Checker) with a WordPress
plugin that lets every editor of library.wheatoncollege.edu see the site's accessibility status in
wp-admin, drill into each page's issues, dismiss reviewed warnings, and rescan a page on demand.

## Decisions

| Topic | Decision |
|---|---|
| Where scans run | GitHub Actions in this repo (daily cron + per-page `workflow_dispatch`) |
| Engine | pa11y with the **axe** runner, WCAG 2.1 AA tags. Errors = axe violations, warnings = axe incomplete. No notices. |
| Matching the local dashboard | Not required. Keep `hideElements` for `.screen-reader-text, .sr-only, body > iframe[style*="visibility: hidden"]`. |
| What is scanned | Published, non-password posts of every public viewable post type (`is_post_type_viewable`). Today: 27 pages. |
| History | Latest result per page only. No trends. |
| Who can view / dismiss | Anyone with `edit_pages` |
| Dismissals | Only **warnings** can be dismissed, after human review. **Errors can never be dismissed.** Key: post + rule code + selector. Logged, with an undo. |
| Emails | None |
| Editor panel | None |
| Transport | Actions pushes results into WordPress over REST; WordPress is the only store |
| Local dashboard | Retired after rollout |

## Components

### Scanner (`scanner/`, `.github/workflows/scan.yml`)

- `scanner/package.json` pins `pa11y` (includes axe runner). `scanner/scan.mjs` is the entry point;
  pure functions live in `scanner/lib.mjs` and are tested with `node:test` (`scanner/lib.test.mjs`).
- pa11y options: `runners: ['axe']`, `standard: 'WCAG2AA'`, `hideElements` as above, a timeout of
  60 s per page, `includeWarnings: true`, `includeNotices: false`. (axe tags follow pa11y's mapping of
  WCAG2AA; if the pinned pa11y does not include 2.1 rules for axe, set axe `runOnly` tags
  `wcag2a, wcag2aa, wcag21a, wcag21aa` via pa11y's runner options.)
- Workflow triggers:
  - `schedule`: daily at 10:00 UTC (06:00 Eastern in summer).
  - `workflow_dispatch` with optional input `url`. If present, scan only that URL; else full scan.
- Secrets: `WPA11Y_SITE` (e.g. `https://library.wheatoncollege.edu`), `WPA11Y_SECRET` (bearer).
- Full scan: `GET {site}/wp-json/wpa11y/v1/pages`, scan each sequentially, `POST /results` per page.
- Single-URL scan: the `url` input must start with `WPA11Y_SITE + '/'` or the run fails before
  scanning. The scanner fetches `/pages` and scans only the entry whose `url` matches; no match fails
  the run.
- A page that fails (timeout, navigation error, or a Cloudflare challenge page detected by title
  `Just a moment...` or `cf-chl` markup) is posted as `{post_id, url, scanned_at, error}`. The run
  exits non-zero at the end if any page failed, so GitHub emails the repo owner.

### Plugin (`wpa11y.php`, `assets/admin.js`, `assets/admin.css`)

Single PHP file (sibling convention), ES5 vanilla JS, no build step. Config passed to JS with
`wp_json_encode()` via `wp_add_inline_script`.

#### Storage

- Post meta `_wpa11y_result` (JSON, not revisioned, does not touch `post_modified`):
  ```json
  {"scanned_at":"2026-09-30T10:04:11Z","url":"…","error":null,
   "issues":[{"type":"error","code":"color-contrast","message":"…","selector":"#main > p.lede",
              "context":"<p class=\"lede\">…","help_url":"https://dequeuniversity.com/rules/axe/…"}]}
  ```
  A failed scan keeps the previous `issues` and sets `error` and `error_at`; the UI marks them stale.
- Post meta `_wpa11y_rescan_requested` (ISO timestamp).
- Custom table `{prefix}wpa11y_dismissals`, created with `dbDelta` on activation / version bump:
  `id, post_id, code, selector, note, user_id, created_at, undone_by, undone_at`.
  Active = `undone_at IS NULL`. Undo sets `undone_*`; Restore inserts a new row. Rows are never deleted.
- Options: `wpa11y_secret_hash` (`hash('sha256', $secret)`), `wpa11y_github_token`,
  `wpa11y_github_repo` (default `tfscharff/wpa11y`), `wpa11y_github_workflow` (default `scan.yml`),
  `wpa11y_github_ref` (default `main`), `wpa11y_last_full_scan`. Token option not autoloaded.

#### REST (`wpa11y/v1`)

| Route | Caller | Auth | Purpose |
|---|---|---|---|
| `GET /pages` | scanner | bearer | `[{id,url,type,title}]` |
| `POST /results` | scanner | bearer | store one page's result; body validated (URL must equal post's permalink after trailing-slash normalization; `type` in error/warning; strings length-capped) |
| `POST /scan-complete` | scanner | bearer | record `wpa11y_last_full_scan` |
| `GET /status?post=ID` | editor | nonce + `edit_pages` | result + active dismissals + rescan state |
| `POST /dismiss` | editor | nonce + `edit_pages` | `{post, code, selector, note}`; rejected unless a current **warning** matches |
| `POST /undismiss` | editor | nonce + `edit_pages` | `{id}` |
| `POST /rescan` | editor | nonce + `edit_pages` | dispatch workflow with the post's own permalink |

Bearer check: `hash_equals($stored_hash, hash('sha256', $token))`. Secret generated by the plugin
(32 random bytes, hex), shown once on the Settings screen for copying into GitHub, then only its hash
is kept. "Regenerate" replaces it.

Rescan: `POST https://api.github.com/repos/{repo}/actions/workflows/{workflow}/dispatches` with
`{"ref":…, "inputs":{"url": permalink}}` and the fine-grained token (Actions: read/write on this repo
only). Non-204 responses are returned to the UI as a readable message.

#### Admin UI

- Menu **Accessibility** (`edit_pages`):
  - **Overview** — summary line (pages, pages with errors, warnings awaiting review, last full scan
    with link to the repo's Actions page); `WP_List_Table` of pages: title, type, errors, open
    warnings, last scanned; sortable; filter views: all / has errors / has warnings / scan failed /
    not scanned.
  - **Page detail** (`&post=ID`) — title, View/Edit links, scanned time (and stale/failed notice),
    **Rescan** button. Sections with headings: Errors, Warnings needing review, Dismissed. Issues
    grouped by code with a disclosure button per group (`aria-expanded`); each instance shows message,
    help link, selector, and context in `<code>`. Warnings have **Dismiss** → inline form with note
    textarea, Confirm/Cancel; focus moves into the form and back to a sensible target afterwards.
    Dismissed items show who/when/note and **Undo**.
  - **Dismissal log** — `WP_List_Table`: date, page, code, selector, user, note, status
    (active / undone / no longer present); filter by status; Undo / Restore actions.
  - **Settings** (`manage_options`) — generate/regenerate secret, GitHub token, repo, workflow, ref.
- Column **A11y** on the list screen of every scanned post type: "N errors · M warnings" linked to
  detail, "No issues", "Scan failed", or "Not scanned".
- Counts everywhere = errors + warnings without an active matching dismissal.
- Rescan flow: button disabled while pending; polite live region announces "Scanning… usually 1–2
  minutes"; poll `/status` every 15 s; when `scanned_at` > requested time, re-render and announce
  "Scan complete: N errors, M warnings"; after 10 minutes stop and say so with a link to Actions.
- Accessibility of the UI itself: WCAG 2.1 AA — real buttons/links, visible focus, no color-only
  signals, headings in order, live-region announcements, no custom modals.

## Error handling

- Missing secret or token: admin notice on plugin screens only, linking to Settings.
- GitHub dispatch failure: inline message with GitHub's status/reason.
- Scanner POST rejected (4xx): logged in the Actions run; run fails.
- Page deleted/unpublished: excluded from `/pages`; its meta stays but it is not listed.

## Testing

- Scanner: `node --test scanner/` covering result mapping, URL validation, challenge detection,
  payload shape.
- Plugin: stub-harness PHP tests (pattern from `wheatonlibrary-specs/tests/`) covering bearer auth,
  results validation, dismissal matching and counts, error-not-dismissable, rescan URL comes from the
  post. `php -l` on every PHP file.
- First plan task is a throwaway spike: a workflow run against one live page to confirm Cloudflare
  lets GitHub runners through. If challenged, add a Cloudflare WAF skip rule on a secret header sent
  by the scanner (secret `WPA11Y_CF_HEADER`), then continue.
- UI verified on the live site after the user installs a release.

## Rollout

1. Release zip via the usual workflow; user installs it.
2. Settings: generate secret → add GitHub secrets `WPA11Y_SITE`, `WPA11Y_SECRET`; create a
   fine-grained token (Actions read/write, this repo) → paste into Settings.
3. Trigger a full scan from Actions; check Overview.
4. Retire the local pa11y-dashboard.

## Out of scope

Emails, editor sidebar panel, trend history, scanning drafts/unsaved edits, site-wide rule ignores,
HTML_CodeSniffer runner.
